# 料金プランによる制約の確認

プランの上限と価格は、このスキルには書いていない。**実行のたびに料金ページから取得し、`plan.md` の「プランの確認」に書いてから人に見せる。** 書き込み（API の作成やコンテンツの登録）はその後。

## 1. 情報を集める

- **契約中のプラン**：人に聞く（管理画面のサービス設定で確認できる）。マネジメント API の `GET /api/v1/service` で取れるのはサービス名だけで、プランは取れない。推測しない。
- **料金ページ**：https://microcms.io/pricing を取得する（Web 取得の機能か `curl -sL`）。価格と上限は HTML にそのまま入っている。取得した日付を記録する。
- **移行先サービスの現状**：既存の API の数はマネジメント API の `GET /api/v1/apis` で確認する。リスト形式のコンテンツ数は、移行用キーに対象 API の **GET・下書きコンテンツの全取得・公開終了コンテンツの全取得** を付け、`GET /api/v1/<endpoint>?limit=0` の `totalCount` で数える。フィルターは付けない。公開中かつ下書き中の同じ ID を二重に数えない。
  - 下書き全取得だけでは公開終了が漏れる。全取得の権限が不足している場合は公開分の件数を全件数として扱わず、権限を確認するか、コンテンツ取得権限を持つマネジメント API の `GET /api/v1/contents/<endpoint>` でメタ情報の `totalCount` を確認する。
  - **オブジェクト形式には `totalCount` がない。** 管理画面またはマネジメント API の単一メタ情報でコンテンツの有無を確認し、0 件または 1 件として別に数える。権限不足などの取得失敗を 0 件と扱わない。
  - 全取得権限は移行用のサーバー側キーに付ける。公開サイト用のキーへ追加しない。権限と取得日を `plan.md` に記録する。

権限の根拠は[公式ヘルプ：コンテンツのエクスポート](https://help.microcms.io/ja/knowledge/data-backup)と[APIキーの権限](https://document.microcms.io/content-api/x-microcms-api-key)。メタ情報で集計する場合は[マネジメント API の一覧取得](https://document.microcms.io/management-api/get-list-contents-management)を参照する。

**料金ページが取得できない、または必要な項目が見つからないときは、覚えている値で埋めない。** 見つからなかった項目を挙げて、人に料金ページで確認してもらう。

## 2. 照らし合わせる項目

料金ページから、契約中のプランの次の値を読む。

| 項目 | 移行計画で数えるもの |
|---|---|
| API 数の上限と、追加 1 個あたりの料金 | 既存の API 数 + 移行で作る API 数（オブジェクト形式も 1 個と数える） |
| コンテンツ数の上限 | 既存のコンテンツ数 + 移行で新規追加する件数（全 API の合計。識別情報が一致する既存コンテンツの更新は加算しない） |
| ファイルアップロードが使えるか | スキーマに `file` フィールドがあるか、本文にファイルへのリンク（PDF など）を入れるか |
| 複数環境が使えるか | 検証環境と本番環境を分けて移行するか |
| API キー数の上限 | 移行用に新しい API キーを発行するか |
| CSV インポートの件数の上限 | CSV インポートを使う場合だけ |
| 1 メディアのサイズ上限 | API の上限（5MB）を超えて管理画面から手で上げるメディアが、この上限に収まるか |
| メンバー数 | 移行後の確認作業のためにメンバーを追加するか |

料金ページに「追加料金」の記載がない項目（コンテンツ数など）は、超えたときにいくらかかるかを推測しない。「問い合わせが必要」と書く。

## 3. `plan.md` に書く形

```markdown
## プランの確認
- 契約中のプラン：<プラン名>（<誰に確認したか>）
- 料金ページ：https://microcms.io/pricing（取得日：YYYY-MM-DD、表示は税抜）

| 項目 | 既存 | 追加 | 合計 | 上限 | 判定 | 超過時の費用・対応 |
|---|---|---|---|---|---|---|
| API 数 | <既存> | <追加> | <合計> | <上限> | ❌ <n> 個超過 | <追加単価> × <n> = 月 <金額>（税抜） |
| コンテンツ数 | <既存> | <追加> | <合計> | <上限> | ✅ | — |
| ファイルアップロード | — | `file` 1 個 | — | 可 | ✅ | — |
| 複数環境 | — | 使う | — | 不可 | ❌ | 上位プランが必要 |

### 超過する項目の代わりの案
- API 数：<例：使っていない種類（メニュー、コメントなど）を移さない、設定類を 1 つのオブジェクト形式 API にまとめる> → 合計 n 個
- ファイル：<例：PDF は外部のストレージに置いてリンクにする>
```

別の種類のタクソノミーを 1 つの API にまとめる案を出すときは、欠点も並べて書く（`microcms.md` の 2 章）。

**プランがわからないうちは、API 数を減らすための設計をしない**（`general.md` の「前提が変わったら」）。

超過する項目があれば、「費用を払う」「代わりの案にする」「プランを変える」のどれにするかを人に選んでもらう。**追加料金がかかる操作（上限を超える API の作成など）は、人が費用に同意するまで実行しない。** API 作成で 402（上限に達した）が返ったら、追加料金を許可して再実行する前に必ず確認する。

追加料金は月額でかかる。移行のためだけに一時的に API を増やした場合は、移行後に削除すれば追加料金は止まる（日割り）。削除は管理画面で人が行うので、削除するかどうかと時期を人に確認する。
